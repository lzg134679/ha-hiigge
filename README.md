# Hiigge 宠物饮水机 · Home Assistant 集成

把 Hiigge（70mai）宠物智能饮水机接入 Home Assistant：看水质、电量、滤芯余量，控制出水方式。

> 不涉及破解授权、不影响设备正常使用、不访问他人设备。

## 能做什么

| 类别 | 实体 |
|---|---|
| 传感器 | 水质 TDS、电量、电池电压、充电状态、滤芯剩余天数、滤芯剩余寿命、滤芯净化次数、滤芯重置日期 |
| 喝水 | 今日喝水次数、今日喝水时长、最近喝水时间、平均每次喝水时长、较日均喝水次数差 |
| 只读状态 | 出水模式、出水档位、感应灵敏度、间歇间隔、设备上报时间、免打扰结束 |
| 报警 | 滤芯到期、缺水、水质异常、水泵堵塞 |
| 其他状态 | 是否连接电源、充电中、夜间免打扰、灯光静音、UV 杀菌（仅设备上报该硬件时出现） |
| 选择 | 出水方式（间歇/感应/持续）、出水档位（低/中/高）、感应灵敏度（浅色/深色）、间歇间隔（15/30/45/60/75/90/105/120 分钟） |
| 开关 | 童锁、强力冲刷 |
| 按钮 | 重置滤芯、清除缺水提示 |

控制类实体（选择/开关/按钮）默认创建，可在集成选项里整体关闭。

**控制走 WebSocket，不是 REST**：`setUserDeviceConfig` 只把配置保存在云端、
不下发给设备，因此所有写操作都走 WS 通道（AES-CBC + protobuf SmartPacket）。
若某次下发失败，实体会在界面上直接报错（`下发…失败: …`），而不是静默失败。

**下发后的状态回读**：设备状态由设备主动上报到云端，命令下发成功≠状态立即更新，
设备执行并回报通常有几秒延迟。如果下发后立刻按云端值刷新界面，就会出现
「改完先跳回旧值、过一阵才变成新值」。集成因此在下发成功后登记**期望值**：

- 最多 90 秒内，实体显示的是你刚设定的值（属性里 `pending: true` 表示仍在等设备确认）
- 期间按 2 / 6 / 16 / 35 秒的节奏回读，设备一旦上报与期望一致的值就立即转为真实状态
- 超时仍未确认，则回退为设备上报值，并在日志里记一条 WARNING（说明命令可能没生效）

命令 id 与字段号全部来自 APK 里的 `PetDrinkingFountainID` 枚举与
`PetDrinkingFountain` 的 oneof case。其中出水方式 / 档位 / 灵敏度 / 滤芯重置
为历史抓包验证；童锁（id=9，case 6）与强力冲刷（id=7，case 5）于 2026-10-30
在真机上逐条下发并回读状态确认（1.5 秒内翻转）。

`OptionalSwitcher` 是枚举而非布尔：`0=NO_FEATURE / 1=ON / 2=OFF`。
本机型不支持的功能会报 `NO_FEATURE`，此时对应开关不会被创建。

**关于喝水记录**：对应 App 首页的「今日 N 次」和详情页的分时折线。
服务端按「截止到当前时刻」统计，所以数值会随当天时间推进而增长，跨天自动归零。
每个喝水实体都带 `hourly` 属性，列出**有喝水的那些小时**及其时长（秒），

```yaml
# 例：今日 7 点喝了 156 秒、9 点 274 秒、13 点 4 秒
hourly:
  - {hour: "07:00", duration_sec: 156}
  - {hour: "09:00", duration_sec: 274}
  - {hour: "13:00", duration_sec: 4}
```

「最近喝水时间」取的就是列表最后一项所在的整点，可直接用于自动化触发。

**关于充电状态**：设备在 `Battery.charge_status` 里上报充电枚举
（APK 中 `SystemProtos$DeviceStatus$Battery$ChargeStatus`：
`0 UNKNOWN / 1 CHARGING / 2 NOT_CHARGING / 3 FULL`），对应三个实体：

- `binary_sensor.…_power_connected`「是否连接电源」：`CHARGING` 与 `FULL` 为开，
  `NOT_CHARGING` 为关 —— 用来判断电源线是否接着，最适合做「断电告警」类自动化
- `binary_sensor.…_battery_charging`「充电中」：仅 `CHARGING` 为开；
  `FULL`（已充满）与 `NOT_CHARGING` 为关，与 HA 二值传感器语义一致
- `sensor.…_charge_status`「充电状态」（诊断）：显示「充电中 / 未充电 / 已充满」，
  用于区分「充电中」为关时到底是没插电还是已经充满

饮水机长期插电、电量满时设备上报的是 `FULL`：此时「是否连接电源」为开、
「充电中」为关，属正常现象。`UNKNOWN(0)` 或字段缺失时三个实体都不会创建，
不会留下永久未知的实体。

轮询间隔默认 60 秒，可在集成选项里调整。

## 安装

**手动安装**

1. 把 `custom_components/hiigge/` 整个目录复制到 HA 的 `config/custom_components/`
2. 重启 Home Assistant
3. 设置 → 设备与服务 → 添加集成 → 搜索「Hiigge 宠物饮水机」

**HACS**（自定义仓库）

1. HACS → 右上角菜单 → 自定义仓库 → 添加 `lzg134679/ha-hiigge`，类别选「集成」
2. 搜索「Hiigge 宠物饮水机」→ 下载 → 重启 Home Assistant
3. 设置 → 设备与服务 → 添加集成 → 搜索「Hiigge」

## 配置

- 集成支持三种登录方式，添加集成时自行选择
- **同一账号只能在一处保持登录**：集成登录会把手机 App 挤下线，反之亦然。
  需要两边同时用时，建议注册小号并加入大号的家庭，集成用小号登录
  （登录方式选择页也有同样提示）
- 登录表单只填账号信息即可：设备品类（`smartType`）由集成按设备型号自动判定，无需手填；
  服务器地址默认国内服，海外账号可在同一页切换

**手机号 + 密码**

填 App 登录用的手机号和密码。密码**不会以明文保存**：登录请求里只有一个
`md5(明文 + 内置 SECRET)` 摘要，集成保存的就是这个摘要，用于 token 失效后
一键重登。摘要不可反推明文，但等同登录凭据，属于敏感数据
（存在 `config/.storage/core.config_entries` 里，随备份一起走）。
已用两个账号实测验证（2026-10-28）。

**token 失效后重新认证**

正常情况下 token 长期有效。若在别处（手机 App）重新登录，HA 里的 token 会立即失效，
集成会提示「需要重新认证」。点击后有三个选项：

1. 用已保存的密码重新登录（无需输入）—— **首选**，一步换回新 token
2. 手机号 + 密码 —— 会顺带刷新保存的摘要（改过密码时用这条）
3. 手机号 + 短信验证码 —— 忘记密码时用

老版本条目第一次升级时还没有摘要，需要用第 2 或第 3 项登录一次；
之后第 1 项就会出现。免密重登于 2026-10-30 实测可用。

**手机号 + 短信验证码**

填手机号 → 云端下发短信 → 填入 6 位验证码登录。忘密码、或账号本来就用验证码登录时走这条。
不需要先装 App 拿密码，也不需要抓包。2026-10-29 实测通过。
同一手机号连续索码会命中服务端频控（约 1 分钟），表单下方勾「重新发送」可重试。
token 有效期较长，登录一次即可长期使用。

**自行抓包填 token**

不想使用账号密码时，可自行抓包，取任意一条请求的 `token` 和 `uuid` 填进去。

配置完成后会自动列出账号下的设备。如果有多个，会让你选一个。
token 失效时集成会提示重新认证，可以选密码、验证码或免密重登。

## 工作原理

```
集成 ──POST + 签名──► api.70mai.com.cn ──► 设备状态（protobuf）
集成 ──WebSocket + AES──► 设备控制（protobuf SmartPacket）
```

签名是本 App 私有的（`sig = md5(...)`），本项目已还原算法，
所以**不需要抓包、不需要手机常驻、不需要任何本地辅助服务**，
装好就能长期运行。

协议细节（接口路径、状态字段表、签名算法、控制命令表）都写在
`custom_components/hiigge/` 的源码注释里，实现所需的信息不依赖外部文档。

## 支持的设备

目前验证的是 **PI3501** 系列（`type 78`，`smartType 49`）。
同系列（PI3505 / PI3506 / PI5501 / Snowball）理论上兼容，
若状态字段有差异，改动 `custom_components/hiigge/proto.py` 的字段表即可。

品类（`smartType`）与硬件型号的对应关系集中登记在
`custom_components/hiigge/catalog.py` 的 `SUPPORTED_PROFILES` 里。新增机型只需要：

1. 在对应品类条目的 `model_types` 里补上新型号编号；
2. 若该机型状态字段表与现有不同，写一个新解码器并让该条目的 `decoder` 指向它。

配置流程与表单都不需要改，用户也无需填写任何技术参数。未登记的硬件型号会记 WARNING
日志（当前仅登记一个品类时按该品类兜底）；若服务端明确返回了未登记的 `smartType`，
集成会直接中止配置并提示补充登记，而不是用错误的字段表解析出一个「看似正常实则全错」
的状态。

喂食器（PI2501 系列）未验证。
